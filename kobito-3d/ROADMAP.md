# 小人一家と汚れた世界 — 改訂ロードマップ

前回の設計図に対して、あなたの回答は3つでした。

| 問い | 回答 |
|---|---|
| 協力プレイの方式 | **オンライン** |
| 対応機 | **スマホ本気・コントローラーは当面なし** |

この3つで設計は大きく変わります。以下は、決定を反映した版です。

## 0. 正直な話：オンラインを選んだ代償と、その払い方

前回「まずローカル画面分割を」と勧めたのは、**面白さが確定する前にネットコードで溺れるのが一番よくある失敗**だからです。
オンラインを選んだ以上、そのリスクは実在します。ただし、**払い方は決まっています**。

> **後から足すのではなく、最初から全部ネット経由で動かす。**

だから今回の土台は、**1人プレイも「自分ひとりのホスト」として同じ経路を通ります**（`Net.start_solo()` は `host()` の別名）。
「1人用を作る → あとで多人数化する」という作り直しが、構造上発生しません。
オンラインを選ぶなら、これが唯一まともなやり方です。中途半端に後付けするほうがずっと高くつきます。

代償として、次の3つは避けられません。順に潰していきます。

1. **どんな処理も「誰が正しいか」を決めないといけない** → 全部サーバが正。実装済み。
2. **家の外へ出すには中継が要る**（費用の話）→ 下の「オンラインを家の外へ出す」。
3. **バグが2台つながないと出ない** → だから CI で毎回2台つないで確認する仕組みを先に入れました。
   実際、書いた直後の1回目で「**後から参加した人の画面に虫が居ない**」という不具合が出ています。
   手で遊んでいたら見逃していた種類のバグです。

## 1. スマホ本気・コントローラーなし、で決まること

### 操作
- 親指2本しかない。**ボタンは3つまで**（こうげき／つかむ／跳ぶ・飛ぶ）。増やしたくなったら、まず自動化を考える。
- 左半分＝仮想スティック、右半分＝カメラ。**画面の下1/3は指で隠れる**ので、大事な情報を置かない。
- 実装のコツ：タッチUIは `Input.action_press()` を叩くだけにしてある。
  だから `player.gd` に「スマホ用の分岐」が1行もない。あとで操作を足すのがラクです。

### 性能
- 描画は **`gl_compatibility`**（古い端末でも動く軽い方式）。影は控えめ、ポリゴンは低く。
- 同時に出す虫は**8匹まで**に制限済み。増やすときは「画面に映っている数」で測ること。
- 敵の位置は10Hz、プレイヤーは20Hz。スマホ回線の上り帯域を食い潰さない設計。

### ⚠️ 配布の費用（無料枠の原則に直撃します）
| 端末 | 配り方 | 費用 |
|---|---|---|
| **Android** | APKを直接インストール（CIが毎回吐きます） | **0円** |
| **Android（Google Play）** | ストア公開 | 初回のみ $25 |
| **iPhone** | TestFlight / ストア（Apple Developer Program） | **年 $99** |
| **iPhone（回避策）** | Web版(PWA)をURLで開く | 0円。ただし動作は重め・通信はWebSocket限定 |

**ここは事前相談が必要な箇所です。** 「ずっと無料枠で回す」原則からすると、
`Android + APK直配り` を主軸、`iPhoneはWeb版で妥協` が素直な線です。
どうしても iPhone にネイティブで入れたいなら、年$99 は避けられません。

## 2. オンラインを家の外へ出す（費用0円から順に）

家の中（同じWi-Fi）なら、いま実装済みの「IPを入れて参加」で**追加費用ゼロ**で遊べます。問題は外です。

| 段階 | やり方 | 費用 | 手間 | 向き不向き |
|---|---|---|---|---|
| **A** | 同じWi-Fi | 0円 | なし | まずこれ。開発中はずっとこれで足りる |
| **B** | どちらかの家でポート開放（24567/UDP） | 0円 | ルータ設定 | 固定IPでないと時々つながらなくなる |
| **C** | **Tailscale / ZeroTier** で2台を同じ仮想LANに入れる | 個人利用は無料枠 | アプリを入れるだけ | **いちばん現実的**。ポート開放不要 |
| **D** | 常時稼働の中継サーバに headless Godot を置く | Oracle Cloud Always Free 等で0円 | 中〜大 | 3人以上・招待制にしたくなったら |

**推奨は C**。あなたの「無料枠を維持する」原則と、手間の少なさの両立点です。
D は「サーバを1台守り続ける」責任が増えるので、遊べることが確定してからで十分。

## 3. マイルストーン（改訂版）

前回の M0〜M6 を、オンライン前提・スマホ前提に組み直したものです。
**★ = この土台にすでに入っているもの。**

### M0｜土台 ★完了
Godotプロジェクト、Git管理、CI（自己点検＋Web書き出し＋APK書き出し）。
→ あなたが最初にやることは「Godotを入れて ▶ を押す」だけになりました。

### M1｜歩ける小人（オンラインで） ★おおむね完了
`CharacterBody3D` + 状態機械、追従カメラ、タッチ操作、2台での位置同期。
**残り**: 端末実機での操作感の詰め（スティックの大きさ・カメラ速度）。ここは実際にスマホで触らないと決まりません。

### M2｜戦える ★骨格は完了
虫のAI（サーバ側）、攻撃判定（サーバ側）、被弾・ダウン・復帰。
**残り**: 攻撃の手応え（ヒットストップ・音・エフェクト）。虫の種類ごとの動きの差。

### M3｜育つ・掃除する ★骨格は完了
XP／レベルアップ／飛行解禁（Lv3）、押せるゴミ、掃除で環境回復度が上がる。
**残り**: 装備ドロップ。排水溝を「入れる空間」にする（いまは板）。

### M4｜夫婦で遊べる状態にする ← **次はここ**
- 2台の実機（PC＋スマホ、あるいはスマホ2台）で30分遊んで、**面白いかを判定する**。
- 子供NPC8人の追従隊列（1体を8回インスタンス化＋バネ追従）。
- 「相手が今どこにいるか」の画面端インジケータ ← オンラインだと迷子が致命的。
- 切断・再接続の面倒を見る（電波が切れるのがスマホの日常）。

**この段階が本当の分岐点です。** ここで「面白い」と思えなければ、世界を広げても面白くなりません。

### M5｜世界を広げる・飛ぶ（1〜2か月）
エリア追加、`GridMap` でのモジュール配置、飛行で行ける上空エリア、汚染源を複数に。
チャンク分割ストリーミングは**スマホのメモリが先に音を上げる**ので、
「1エリア読み切り＋エリア間は暗転」で十分。凝るのは最後。

### M6｜縦切り完成
見た目（無料アセット差し替え）・音・UI・タイトル〜クリア。人に遊んでもらう。

### M7｜そのあと
中継サーバ（上のD）、3人以上、ボス、Google Play公開。

## 4. データで調整する（あなたの得意分野の活かし方）

敵の数値は `data/*.tres` に外出ししてあります。`ant.tres` の `move_speed` を触るだけで速さが変わります。
将来、Google Sheets の表から `.tres` を生成する GitHub Actions を足せば、
**「スプレッドシートを編集したら次のビルドに反映」** が作れます。GAS/Sheets運用の経験がそのまま武器になります。

## 5. 今週やること

1. Godot 4.7 を入れて、`kobito-3d` を開いて ▶ を押す。「ひとりで始める」で庭を歩く。
2. PCでホスト、スマホ（同じWi-Fi）で参加して、**2人で虫を殴ってみる**。

   - iPhone なら、`kobito-web` を適当な場所に置いてURLで開く（このときは通信路を **WebSocket** に）。
