# 複数店舗（23店舗展開）プラン — 携帯ホーム風の店舗アイコン画面

> ステータス: **仕様確定・実装は2店舗目が決まってから**（2026-06-28 合意）
> 現在は すさび湯三条 の1店舗のみ運用中。

## やりたいこと（ユーザー要望）
- 携帯のホーム画面のように、**店舗ロゴのアイコン**を並べた「店舗選択ホーム」。
- 店舗が増えたら**横（右）スクロール**でアイコンが並ぶ。
- アイコン下に**識別名**を表示（屋号がかぶるため）。例: すさび湯 → 下に「河原町三条／歌舞伎町／三宮」。
- アイコンを**長押し → −（マイナス）で非表示**にできる。
- 別画面で**再表示する店舗を複数選択**できる。
- 担当外（通知不要）の店舗は隠せる。

## 通知の絞り込み（確定）
- **「表示中の店舗」だけに通知**が届く。非表示にした店舗の通知は来ない。
- 端末ごとに、表示中＝担当する店舗の購読だけを有効化する。

## データ構成（¥0のまま実現）
- **店舗一覧シート**（新タブ `店舗` など）: 列の例
  `storeId | 屋号(full) | shortName(識別名) | logoUrl | gasUrl | sheetId | enabled`
- 各店の**ロゴ**は Drive かリポジトリ public に置き、jsDelivr 等で配信。
- 各店の**購読リスト**は店舗ごとに分ける（既存の `購読` タブを storeId 付きにするか、店舗シートごとに持つ）。

## PWA 画面遷移
1. 起動 → **店舗選択ホーム**（ロゴ＋識別名のグリッド、横スクロール）。
2. 店舗タップ → その店舗の **確認 / 見本**（現行画面）。屋号はヘッダーに表示済み。
3. アイコン**長押し → −**で非表示（localStorage に hidden 店舗を保存）。
4. 「店舗を表示/非表示」設定画面で**複数選択して再表示**。
5. 表示中の店舗に対してのみ Web Push を購読（通知の絞り込み）。

## 実装メモ
- 屋号は既に `STORE_NAME`（config.js）でヘッダー表示済み。多店舗時は店舗ごとに切替。
- GAS は店舗ごとに分けるか、1つのGASで storeId を受けて分岐するかは2店舗目決定時に判断。
- 既存の単店運用（すさび湯三条）はそのまま1つ目のアイコンとして組み込める。

## 着手トリガー
- 2店舗目の **屋号・ロゴ・アカウント（IG/Drive/シート）** が決まったら着手。

## 画像ホスティングと30店舗スケール（¥0維持の方針）

> 結論: **保存=GitHub（無料）／配信=jsDelivr CDN（無料・実質無制限）** のまま 30 店舗でも ¥0。
> カード不要。Cloudinary等の外部は不要（30店舗だと動画配信量で無料枠を超えるため不採用）。

### なぜ¥0で回るか
- jsDelivr は公開GitHubリポを配信する無料CDN。**配信量に課金がない**ので店舗が増えても配信コストは¥0。
- GitHub のリポ保存も無料。

### 唯一の注意点＝GitHubの「コンテンツ作成レート制限」
- 短時間に大量コミット（1ファイル=1コミット）すると 403（作成レート制限）に当たり、
  一時ホスト(litterbox)へフォールバック→数日で消える、という事故が起きる。
- **通常運用は 1店舗あたり 1日3〜6コミットだけ**（prepare.py は2日後ぶんの3枠のみ生成）なので、
  単店では基本当たらない。今日の事故はテストの連発アップが原因。

### 実装済みの安全網（恒久）
1. `poster.up(cdn)`: 永続(jsDelivr→jsDelivr再試行→R2)優先＋一時(litterbox等)を最終フォールバック＝**保存は絶対失敗しない**。
2. `_u_jsdelivr`: 403/429時に 6,12,24,48秒 待って**再試行**＝一時的なレート制限を乗り越え永続保存に成功。
3. `insights.py heal`: 一時保存に落ちた分を、消える前に**毎時 jsDelivr へ昇格**（1回8件）。

### 30店舗で守るべき運用ルール（多店舗ロールアウト時に適用）
- **各店の生成cronを分散**（全店同時刻にしない）。例: 店舗ごとに prepare の cron を数分〜数十分ずらす。
  - 30店 × 3枠を同時刻に上げると ~90コミットが集中して制限に当たるが、分散すれば 1時間あたり数件で安全。
- **見本(samples)一括生成**は ~13コミットのバーストになるので、新パターン追加時など必要時のみ手動実行（再試行で吸収）。
- これらで 30店舗でも ¥0・画像消失なしを維持できる。バッチコミット(Git Data API)は通常運用では不要（過剰実装）。
